Veredicto — Monólito Modular
A decisão foi tomada com critérios objetivos. Microserviços serão a fase 2 — extração cirúrgica dos schemas já isolados.
Monólito Modular venceu em 5 de 6 critérios vs Microserviços: transações ACID (PCI obrigatório), audit log centralizado (LGPD), custo de infra inicial (1 cluster vs N), debugging (stack trace local) e tamanho do time. A fronteira lógica de hoje (schemas PG por módulo) é a fronteira física do microserviço de amanhã.

Arquitetura › Decisões ADR
15 Decisões Arquiteturais
Cada decisão tem escolha, alternativas descartadas e motivo. Nada existe só na cabeça de alguém. Reverter qualquer ADR exige nova ADR aprovada pelo Tech Lead.
ADR-001ORM: EF Core 8 vs Dapper
QueryFilter multi-tenant automático por reflection — Dapper exige WHERE manual em toda query. Esquecer = vazamento de dados entre tenants.
✓ EF Core 8Dapper
ADR-002Identity: Keycloak 24 vs JWT hardcoded vs Auth0
JWT hardcoded foi o bug crítico do legado. Auth0: $250+/mês a escala + lock-in. Keycloak: open source, OIDC, MFA, SSO, on-premise.
✓ Keycloak 24JWT hardcoded Auth0
ADR-003Cache: Valkey 7 vs Redis 7
Redis mudou para BSL em 2024 — risco comercial para SaaS. Valkey é o fork OSS pela Linux Foundation com paridade total.
✓ Valkey 7Redis 7
ADR-004Secrets: HashiCorp Vault vs Azure Key Vault
Cloud-agnostic. Dynamic secrets. On-premise. Zero custo. Azure Key Vault: lock-in e custo por operação.
✓ HashiCorp Vault OSSAzure Key Vault
ADR-005IaC: OpenTofu vs Terraform
HashiCorp mudou Terraform para BSL em 2023 — mesmo risco do Redis. OpenTofu é o fork OSS com paridade total.
✓ OpenTofu 1.7+Terraform
ADR-006Banco: PostgreSQL 16 vs SQL Server
Open source, zero licença. RLS nativo. pgvector, pgcrypto, pg_trgm. SQL Server: licença comercial crescente com escala.
✓ PostgreSQL 16SQL Server
ADR-007Frontend: Nuxt 3 vs Blazor WASM vs Next.js
Blazor: stack diferente, time dividido, incompatível com Electron. Nuxt 3 reutiliza 100% no Desktop via Electron.
✓ Nuxt 3Blazor WASM Next.js
ADR-008Desktop: Electron + Nuxt 3 vs Tauri
Reutiliza 100% do código Nuxt sem reescrita. Tauri: revisitar Bloco 9 quando o time tiver expertise Rust.
✓ Electron + Nuxt 3Tauri (Rust)
ADR-009Mobile/PDV: React Native vs Flutter
Flutter requer Dart — stack separada. React Native aproveita os devs JavaScript já no time.
✓ React Native + ExpoFlutter
ADR-010IDs: Guid vs long sequencial
Offline-first: geração local sem banco, sem colisão em merge. Long expõe volume e não funciona offline.
✓ Guidlong sequencial
ADR-011Sync offline: SyncId+SyncVersion vs timestamp
Detecção de conflito robusta. Timestamp tem clock skew entre dispositivos — gera conflitos fantasma.
✓ SyncId + SyncVersiontimestamp puro
ADR-012Multi-tenancy: QueryFilter ContextBase vs RLS puro
Flexibilidade de troca de estratégia sem mudar queries. RLS como segunda barreira adicional.
✓ QueryFilter via ContextBaseRLS puro
ADR-013Proxy: Caddy 2 vs Nginx
HTTPS automático, HTTP/3, configuração 6x mais simples. Nginx: renovação de certificados manual.
✓ Caddy 2Nginx
ADR-014Lib NF-e: Hercules.NET vs alternativas
Em produção nos 20 clientes. Homologada com todas as UFs. Substituição exige ADR + 90 dias de testes mínimos.
✓ Hercules.NET.NFe.NFCenfce-lib DFe.NET
ADR-015Jobs: Quartz.NET vs Hangfire
Clustering nativo com PostgreSQL. Hangfire requer banco separado ou SQL Server.
✓ Quartz.NET 3.xHangfire
Arquitetura › DDD & Dados
DDD & Modelo de Dados
Bounded contexts com EntidadeSaaSBase, Value Objects e Domain Events. Outbox Pattern para toda comunicação entre módulos. Sem DbContext cruzado.
EntidadeSaaSBase — herdada por toda entidade
public abstract class EntidadeSaaSBase : Notifiable<Notification>, ISyncable { public Guid Id { get; private set; } // PK — gerado localmente, offline-safe. Nunca long. public Guid SyncId { get; private set; } // chave estável para sync — nunca muda public string TenantId { get; private set; } // QueryFilter automático por reflection public int SyncVersion { get; private set; } // detecta conflitos offline public DateTime CriadoEm { get; private set; } // DateTime.UtcNow — nunca .Now public DateTime? AlteradoEm { get; private set; } public DateTime? DeletadoEm { get; private set; } // soft delete — nunca context.Remove() public string? CriadoPor { get; private set; } // userId Keycloak public void MarcarAlterado(string alteradoPor) { AlteradoEm = DateTime.UtcNow; SyncVersion++; } public void Deletar(string deletadoPor) { DeletadoEm = DateTime.UtcNow; } public bool EstaAtivo() => DeletadoEm == null; public bool IsValid => !Notifications.Any(); } // ContextBase aplica por reflection para TODAS as entidades automaticamente: // WHERE tenant_id = {TenantProvider.GetTenantId()} AND deletado_em IS NULL

Agentes transversais — ativos em todas as fases

⬡ Context Agent [GLOBAL] — .cursorrules

Injeta domain knowledge completo do Epros em todos os agentes — EntidadeSaaSBase, regras fiscais BR, multi-tenancy, 15 ADRs, regras SEMPRE/NUNCA — via .cursorrules na raiz do repositório. Sempre ativo, nunca invocado manualmente.
Quem usa: Todos (indiretamente)

🔒 Security Agent [TRANSVERSAL]

Revisa qualquer código com lens OWASP Top 10, LGPD, PCI DSS. Retorna vulnerabilidades categorizadas: 🔴 crítico / 🟡 alto / 🟢 médio, com localização e correção.
Quem usa: Dev Backend · Dev Sênior · Tech Lead

📝 Docs Agent [TRANSVERSAL]

Gera e atualiza documentação viva — changelog, ADRs, comentários XML doc, README — a partir de decisões técnicas ou diffs de PR.
Quem usa: Todos — após cada entrega significativa

👁️ Code Review Agent [TRANSVERSAL]

Revisão estruturada de PR — padrões Epros (EntidadeSaaSBase, CQRS, multi-tenancy, snake_case). Retorna: 🔴 bloqueante / 🟡 aviso / 🔵 sugestão. Obrigatório antes de qualquer merge.
Quem usa: Dev Backend · Dev Frontend · Tech Lead

DateTime.UtcNow — nunca DateTime.Now
Guid para IDs — nunca long ou int
Soft delete via entidade.Deletar(userId)
ITenantProvider via DI scoped — nunca estático
CQRS — zero lógica no Controller
Outbox Pattern para todo Domain Event
Schema por macrodomínio no mapping EF Core
snake_case nas colunas PostgreSQL
Precision(18,2) em todo campo decimal
Índice composto (tenant_id, campo_negocio)
Índice único em sync_id
❌ NUNCA
context.Remove() — soft delete apenas
Lógica de negócio no Controller
DbContext de outro módulo injetado
Variável estática de TenantId
JWT ou secret hardcoded no código
Connection string em appsettings de produção
long ou int como ID de entidade
Domain Event publicado diretamente (sem Outbox)
SQL raw sem parâmetros
Cross-schema query sem documentação
DateTime.Now em qualquer lugar
IgnoreQueryFilters() sem justificativa e teste
