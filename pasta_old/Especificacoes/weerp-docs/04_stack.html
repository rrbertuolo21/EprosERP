⬡ Runtime & Framework
ASP.NET Core 8v8.0 LTSMANTER
Runtime open source MIT. Performance #1 no TechEmpower Framework Benchmarks — acima de Go, Java e Node em JSON serialization e plaintext. LTS até novembro 2026. Roda em Alpine Linux com imagem de 80MB. Minimal API suportada mas não usada — Controllers para clareza e Swagger automático.
Quem usa em produção: Discord (mensagens), Stack Overflow (Q&A), Cloudflare (edge workers), Alibaba (serviços internos).
MediatRv12.xMANTER
Mediator pattern para CQRS. Behaviors (pipeline) para cross-cutting concerns: logging, validação FluentValidation, auditoria, rate-limit por command — sem poluir os handlers de negócio. IRequest<TResponse> garante tipagem completa. Zero reflexão em runtime crítico.
Alternativa considerada: Carter (Minimal API) — descartado por perder Swagger automático e comportamento de Behaviors.
Fluntv2.xMANTER
Validação de domínio dentro dos agregados. Notifiable<Notification> acumula erros sem lançar exceção — permite retornar lista completa de erros ao invés de falhar no primeiro. Integrado ao CommandResult. EntidadeSaaSBase.IsValid é a porta de saída.
Alternativa: DataAnnotations — descartado por poluir entidades com atributos de apresentação. Domain deve ser ignorante de frameworks externos.
FluentValidationv11.xMANTER
Validação declarativa de Commands e Queries no pipeline MediatR. Regras por tenant via IValidator customizado injetado via DI. Retorna 422 com lista de erros antes de chegar no Handler. Testes de validação são simples e legíveis.
Responsabilidade distinta do Flunt: FluentValidation valida o input externo (Command), Flunt valida as invariantes do domínio (Entidade).
Quartz.NETv3.xNOVO
Agendamento de jobs com persistência no PostgreSQL (evita jobs duplicados em multi-instância). Usado para: Outbox processor (polling a cada 5s), retenção de dados LGPD, fechamento contábil automático, alertas de vencimento de títulos, rotação de secrets Vault.
Alternativa: Hangfire — mais simples, mas requer banco separado ou SQL Server. Quartz tem suporte a cron expressions complexas e clustering nativo.
Serilogv3.xMANTER
Logs estruturados JSON com enrichers automáticos de tenantId, traceId e userId em cada linha de log. DataMaskingMiddleware garante que CPF/PAN nunca aparecem. Sinks: Console (dev), Loki (produção). Destructor policy para objetos complexos.
Alternativa: NLog — descartado por configuração mais verbosa e enrichers menos flexíveis.
📦 NuGet packages críticos
Hercules.NET.NFe.NFCev2026.3.15.14CRÍTICO
Biblioteca para emissão de NF-e (modelo 55), NFC-e (modelo 65), NFS-e, CT-e. Já em produção nos 20 clientes Epros.ERP. Homologada com SEFAZ de todos os estados. Suporta contingência offline (DPEC e FS-DA). Não substituir sem validação extensiva em homologação.
Esta lib é um ativo crítico — representa anos de ajustes para compliance com cada UF. Qualquer troca requer plano de migração e testes em todos os ambientes estaduais.
OpenTelemetry .NET1.8+NOVO
Instrumentação automática de ASP.NET Core, EF Core, Valkey (via StackExchange.Redis), HttpClient e Quartz. Traces, métricas e logs unificados via OTLP. TraceId propagado até o ProblemDetails retornado ao cliente — suporte facilita debugging em produção.
Polly8.xNOVO
Resiliência para chamadas externas: retry com backoff exponencial, circuit breaker, timeout e bulkhead isolation. Usado em: chamadas SEFAZ (NF-e), gateways de pagamento, Vault, Keycloak. Configurado via HttpClientFactory + AddResilienceHandler.
🗄 Banco de dados principal
PostgreSQL 1616.x alpineCRÍTICO
12 schemas separados por macrodomínio. Extensões ativas: uuid-ossp (UUIDs), pg_trgm (busca trigram full-text), unaccent (busca sem acento), pgcrypto (colunas PII criptografadas). Row-Level Security configurado como segunda barreira. Particionamento por data para tabelas de auditoria e outbox. pgvector planejado para fase IA/ML.
Substituiu SQL Server do legado: open source, zero licença comercial, superior para JSONB, melhor ecossistema de extensões, Row-Level Security nativo.
EF Core 8 + Npgsql8.0.xCRÍTICO
ORM com convenção snake_case global via UseSnakeCaseNamingConvention(). QueryFilter multi-tenant + soft delete aplicado por reflection em ContextBase — nunca manual. Migrations versionadas por DbContext (um por módulo). Split queries para evitar N+1 em includes. Compile models para performance em produção.
Alternativa considerada: Dapper — descartado porque exigiria QueryFilter manual, risco de esquecer tenant em alguma query. EF Core garante por construção.
⚡ Cache & Locks
Valkey 77.x alpineCRÍTICO
Fork open source do Redis criado após a mudança de licença (BSL) em 2024. Mantido pela Linux Foundation com contribuidores da AWS, Google, Oracle e Ericsson. API 100% compatível com Redis — usa StackExchange.Redis como client sem mudança. Usos no Epros: cache de Connection Router (TTL 5min), sessões Keycloak, rate-limit sliding window, locks distribuídos de estoque (SETNX).
Por que não Redis: mudança para BSL em 2024 cria risco comercial para SaaS que competem com Redis Ltd. Valkey é o sucessor oficialmente open source.
📁 Object Storage
MinIORELEASE.2024NOVO
Object storage S3-compatible self-hosted. API idêntica à AWS S3 — usa AWSSDK.S3 como client. Armazena: XMLs de NF-e/NFC-e, PDFs DANFE, anexos GED, backups de tenant, exports LGPD. Replicação multi-site para disaster recovery. Buckets separados por tenant com políticas de acesso por IAM própria do MinIO.
Substituível por qualquer S3 (AWS, GCS, Azure Blob) sem mudar uma linha de código da aplicação — só a connection string no Vault.
🔐 Identity & Access Management
Keycloak 2424.0CRÍTICO
Identity Provider completo: OIDC/OAuth2/SAML 2.0. MFA nativo (TOTP via Google Authenticator, WebAuthn/FIDO2, SMS). Federation com Active Directory/LDAP para clientes enterprise. Dois realms separados: epros-admin (operação interna) e epros-tenant (clientes). Claim tenantId injetado no JWT via Protocol Mapper. Token de acesso: 15min. Refresh token: uso único, rotacionado.
Substituiu JWT hardcoded do legado. Quem usa: Red Hat (SSO corporativo), Airbus, Adidas, Intesa Sanpaolo. CNCF project.
🔑 Secrets Management
HashiCorp Vault OSS1.16.xCRÍTICO
Gestão centralizada de secrets. Dynamic secrets para PostgreSQL: Vault gera usuário+senha temporários a cada acesso, rotaciona automaticamente — connection string nunca fixa. Secrets Engines usados: KV v2 (API keys, certs digitais), Database (PostgreSQL dynamic), PKI (certificados TLS internos). Audit log nativo de cada acesso a secret. AppRole auth para CI/CD.
Alternativa: AWS Secrets Manager / Azure Key Vault — descartados por criar dependência de cloud. Vault roda on-premise com paridade funcional total.
🌐 Reverse Proxy & TLS
Caddy 22.xNOVO
Reverse proxy com HTTPS automático via Let's Encrypt (ACME) — zero configuração manual de certificado. HTTP/3 nativo (QUIC). TLS 1.3 por padrão, TLS 1.2 como fallback. Rate limiting nativo. HSTS preload. Headers de segurança automáticos (X-Frame-Options, CSRF, CSP). Caddyfile é declarativo e versionável.
Alternativa: Nginx — descartado por configuração verbosa, certificados manuais e ausência de HTTP/3 nativo. Caddy faz em 10 linhas o que Nginx faz em 60.
🛡 Segurança de código e runtime
TrivylatestNOVO
Scanner de vulnerabilidades para imagens Docker, pacotes NuGet/npm e manifests IaC (Dockerfile, Compose, K8s). Integrado ao CI — CVE crítico ou alto bloqueia o pipeline. Gera relatório SARIF para GitHub Security tab. Zero configuração para uso básico.
Falco0.37+FASE 2
Runtime security para containers em Kubernetes. Detecta comportamento anômalo em produção: processo inesperado dentro de container, acesso a arquivos sensíveis, shell aberto em container, conexão de rede não autorizada. Alertas para Grafana/PagerDuty.
OWASP ZAP2.14+NOVO
DAST — Dynamic Application Security Testing. Varredura ativa da API em ambiente de staging. Detecta: SQL injection, XSS, SSRF, autenticação fraca, endpoints sem autorização, rate limit bypassável. Roda automaticamente no pipeline de staging antes de release.
Os 4 componentes de observabilidade formam um stack coeso — todos open source, todos integrados ao Grafana como pane único. Substitui Datadog (~$30k/ano), Azure Monitor e CloudWatch sem perda funcional.
📊 Stack Grafana OSS — 4 pilares
Grafana10.xNOVO
Dashboards unificados para métricas (Prometheus), logs (Loki) e traces (Tempo) — correlação com um clique. Alerting nativo com notificações para Slack, PagerDuty, e-mail. Provisioning via YAML/JSON versionado no Git. Dashboards separados por módulo e por tenant para clientes Enterprise.
Prometheus2.xNOVO
Scraping de métricas da API .NET via OpenTelemetry Prometheus exporter. Métricas obrigatórias por módulo: request rate, error rate, latência P50/P95/P99, tamanho do outbox pendente, lag de sync offline. PromQL para SLO queries. Retenção de 15 dias por padrão.
Loki2.xNOVO
Log aggregation sem indexação de conteúdo — só labels (tenantId, moduleId, level, traceId). Serilog sink para Loki. LogQL para queries. Correlação direta com Tempo via traceId. Retenção configurável por módulo — logs de auditoria LGPD: 12 meses mínimo.
Tempo2.xNOVO
Distributed tracing com OTLP via gRPC (porta 4317) e HTTP (4318). TraceId gerado no middleware e propagado até o ProblemDetails retornado ao cliente. Visualização de spans: HTTP → MediatR Handler → EF Core query → Valkey → Outbox. Integrado ao Grafana para salto direto de log → trace.
📏 SLOs definidos por nível de serviço
Leitura (GET)P95 < 200msSLO
Medido via Prometheus histogram. Alertar em P95 > 150ms (warning) e > 200ms (critical). Dashboard por módulo para identificar regressões específicas.
Escrita (POST/PUT)P95 < 500msSLO
Inclui validação, persistência e enqueue do Outbox. Alertar em P95 > 400ms. Operações fiscais (NF-e) têm SLO separado de < 3s incluindo SEFAZ.
Disponibilidade99.9% / mêsSLO
Calculado via Prometheus uptime query. Error budget de 43min/mês. Downtime planejado (migrations) notificado com 24h de antecedência.

Infra reproduzível: provisionamento de clusters PostgreSQL, buckets MinIO, realms Keycloak, configurações Vault. State no backend S3 (MinIO). Plano de execução sempre revisado antes de apply.
Por que não Terraform: mesma mudança de licença que levou ao fork do Redis → Valkey. OpenTofu tem paridade funcional e é mantido ativamente.

Princípio de seleção de stack

① Licença permissiva

MIT ou Apache 2.0. Qualquer componente com BSL, SSPL ou licença comercial é candidato a substituição — como já aconteceu com Redis (→ Valkey) e Terraform (→ OpenTofu).

② Maturidade comprovada

Mínimo 3 anos de projeto, comunidade ativa, usado por empresas Fortune 500 ou equivalente. Não adotamos "the next big thing" sem histórico.

③ Cloud-agnostic

Qualquer componente que só funcione em AWS, Azure ou GCP é descartado. A stack deve rodar identicamente em VPS de €20/mês ou data center próprio do cliente.
