Como o Entitlement Engine funciona
Mudança de plano = transação na tabela catalog.tenant_modules — sem redeploy, sem restart, sem downtime. Efeito imediato na próxima request do tenant.
Ativação de módulo

Bloqueio automático por pré-requisito

Ao tentar ativar um módulo, o Entitlement Engine verifica pré-requisitos em tempo real. Se não satisfeitos, retorna 422 Unprocessable Entity com mensagem indicando quais módulos precisam ser habilitados primeiro. Zero ativação incorreta.

Desativação de módulo

Dados históricos sempre preservados

Módulo desabilitado não apaga dados. O schema PostgreSQL permanece intacto — apenas o acesso é revogado. Reativação é instantânea. Dados de anos anteriores ficam disponíveis no momento da reativação.

Zero código condicional no runtime

Como funciona na prática

Módulo desabilitado para o tenant = nenhum listener de Domain Event registrado na inicialização. O código não tem if (moduloAtivo) em nenhum lugar — o próprio event bus não entrega eventos para handlers de módulos inativos. Isso garante que código de módulo desabilitado nunca executa.

Entitlement check por request

O middleware ModuloTenantMiddleware valida macrodomínio + submódulo ativo para o tenant em cada request HTTP. Retorna 403 Forbidden se inativo — antes de chegar ao handler de negócio. A UI também consome /api/me/entitlements no boot e renderiza apenas menus de módulos ativos.
