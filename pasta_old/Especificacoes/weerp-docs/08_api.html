API Reference

Documentação completa da API REST do Epros. Base URL: https://api.epros.com.br/api/v1 · Formato: JSON · Auth: JWT Bearer (Keycloak 24)

Fluxo de autenticação — Keycloak 24 OIDC
1

Obter token de acesso

Faça um POST para o Keycloak com suas credenciais. Em produção, use Authorization Code Flow + PKCE (nunca client_secret no frontend).

POST http://auth.epros.com.br/realms/epros-tenant/protocol/openid-connect/token Content-Type: application/x-www-form-urlencoded grant_type=password &client_id=epros-api &username=usuario@empresa.com &password=senha123 &scope=openid profile email
2

Resposta — token JWT

O token de acesso expira em 15 minutos. Use o refresh_token (uso único, rotacionado) para renovar sem pedir senha novamente.

{ "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6Ikp...", "expires_in": 900, "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6Ikp...", "refresh_expires_in": 86400, "token_type": "Bearer" }
3

Usar o token nas requisições

Inclua o Authorization header em toda request. O middleware extrai o tenantId do claim JWT automaticamente — não é necessário passar o tenant explicitamente.

GET /api/v1/financeiro/contas-pagar Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6Ikp...
4

Claims do JWT

O token contém os claims usados pelo backend para autenticação, autorização e isolamento multi-tenant.

// Payload do JWT decodificado { "sub": "a3f8e2d1-...", // userId "email": "joao@empresa.com", "tenantId": "tenant-abc123", // isolamento multi-tenant "realm_access": { "roles": ["financeiro.contas_pagar.write", "vendas.read"] }, "exp": 1716900000 // 15min após emissão }
Renovação de token
POST http://auth.epros.com.br/realms/epros-tenant/protocol/openid-connect/token grant_type=refresh_token &client_id=epros-api &refresh_token=eyJhbGciOiJIUzI1NiIsInR5cCI6Ikp...
Refresh tokens são de uso único e rotacionados — um novo é emitido a cada renovação. Armazene sempre o mais recente. Usar um refresh token antigo invalida a sessão inteira.

LGPD — Dados do titular
GET /plataforma/meus-dados/exportar Portabilidade — exportar todos os dados do usuário (LGPD Art. 18-V) ▼

Gera um ZIP com JSON estruturado de todos os dados pessoais do titular autenticado. Para volumes grandes, retorna 202 Accepted e envia por e-mail quando pronto.

// Resposta imediata para volumes pequenos // Content-Type: application/zip // Content-Disposition: attachment; filename="meus-dados-2025-03-10.zip" // Para volumes grandes: 202 Accepted { "sucesso": true, "mensagem": "Exportação em processamento. Você receberá um e-mail quando estiver pronta." }
DELETE /plataforma/meus-dados/eliminar Direito ao esquecimento — anonimizar dados pessoais (LGPD Art. 18-VI) ▼
Dados necessários por obrigação legal (ex: dados contábeis por 5 anos) não são anonimizados — o sistema informa quais ficaram e por qual motivo legal.
{ "confirmacao": "CONFIRMO A ELIMINAÇÃO DOS MEUS DADOS" } // → 200: { anonimizados: 47, preservadosPorLei: 12, detalhes: [...] }

Códigos HTTP utilizados
200OKRequest processado com sucesso. Usado em GET, PUT e ações (baixar, cancelar).
201CreatedRecurso criado com sucesso. Retorna o objeto criado com ID.
202AcceptedRequest aceita para processamento assíncrono. Ex: exportação LGPD para volumes grandes.
400Bad RequestRequest malformado. JSON inválido, tipo errado, parâmetro obrigatório ausente no path.
401UnauthorizedToken ausente, inválido ou expirado. Renovar via refresh token.
403ForbiddenAutenticado mas sem permissão. Módulo inativo para o tenant ou role insuficiente.
404Not FoundRecurso não encontrado. Pode ser soft-deleted (invisível) ou de outro tenant.
409ConflictConflito de estado. Ex: tentar baixar uma conta já cancelada.
422Unprocessable EntityValidação de negócio falhou. Retorna lista de erros do Flunt/FluentValidation.
429Too Many RequestsRate limit atingido. Header Retry-After indica quando tentar novamente.
500Internal Server ErrorErro inesperado. Retorna ProblemDetails com traceId para correlação nos logs.
503Service UnavailableAPI em manutenção ou banco indisponível. Header Retry-After presente.

Idempotência
Para operações críticas (emitir venda, baixar título), envie o header Idempotency-Key: {uuid}. A mesma key retorna o resultado da primeira execução sem processar novamente — seguro para retry automático em falhas de rede.
POST /api/v1/vendas Authorization: Bearer ... Idempotency-Key: 7f3a9c12-4e8b-4d2f-9a1c-8b6e3f7d2a4c Content-Type: application/json { ... }
