Modelo de Dados

Mapeamento físico do banco de dados relacional Epros. Estruturas de tabelas, chaves primárias, estrangeiras, índices e políticas automáticas de multi-tenancy.

Princípios Físicos de Modelagem

O Epros utiliza o PostgreSQL 16 estruturado sob 12 schemas lógicos para manter o desacoplamento do monólito modular. As convenções e os filtros globais são gerados e aplicados programaticamente via EF Core em `ContextBase`.

Row-Level Security (RLS)

1. Toda tabela associada a inquilinos possui a coluna `tenant_id` física.

2. O interceptador `TenantRlsInterceptor` do EF Core executa `SET LOCAL app.current_tenant_id = '{id}'` em cada conexão antes das queries.

3. A política do banco garante que um tenant nunca consulte dados de outro: `tenant_id = current_setting('app.current_tenant_id')`.

Convenções de Nomeação

1. **snake_case**: Nomes de tabelas, colunas, chaves primárias, chaves estrangeiras e índices são mapeados em minúsculas com underscores.

2. **Decimais**: Precisão financeira global configurada para `NUMERIC(18,2)` para todos os campos decimais.

3. **Sync Engine**: Ínclui a coluna `sync_id` com índice único composto em todas as entidades para permitir sincronização offline resiliente.

Colunas Herdadas da EntidadeSaaSBase

Toda entidade mapeada no banco de dados que herda de `EntidadeSaaSBase` possui as seguintes colunas padrões:

Coluna Tipo PostgreSQL Modo Chave / Índice Descrição
id UUID NOT NULL PK Chave primária física (gerada localmente via GUID sequencial).
sync_id UUID NOT NULL UNIQUE INDEX Identificador único estável usado para sincronização móvel e contingência.
tenant_id VARCHAR(100) NOT NULL INDEX Identificador do inquilino usado na política RLS e filtragem lógica.
sync_version INTEGER NOT NULL — Controle de versão incremental usado para detecção de conflitos de concorrência.
criado_em TIMESTAMPTZ NOT NULL — Data de criação do registro (sempre gravada em UTC).
alterado_em TIMESTAMPTZ NULL — Data da última alteração do registro.
deletado_em TIMESTAMPTZ NULL — Data de exclusão lógica (Soft Delete — queries ignoram registros se preenchido).
criado_por VARCHAR(100) NULL — Identificador do usuário (Keycloak sub) que criou o registro.
alterado_por VARCHAR(100) NULL — Identificador do usuário que alterou o registro.
