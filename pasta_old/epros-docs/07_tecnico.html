EntidadeSaaSBase — implementação completa
public abstract class EntidadeSaaSBase : Notifiable<Notification>, ISyncable { public Guid Id { get private set; } public Guid SyncId { get private set; } public string TenantId { get private set; } = ""; public int SyncVersion { get private set; } public DateTime CriadoEm { get private set; } public DateTime? AlteradoEm { get private set; } public DateTime? DeletadoEm { get private set; } public string? CriadoPor { get private set; } public string? AlteradoPor { get private set; } // EF Core precisa de construtor protegido sem parâmetros protected EntidadeSaaSBase() { } protected EntidadeSaaSBase(string tenantId, string criadoPor) { Id = Guid.NewGuid(); // Guid — nunca long SyncId = Guid.NewGuid(); // chave estável para sync TenantId = tenantId; CriadoEm = DateTime.UtcNow; // UtcNow — nunca Now CriadoPor = criadoPor; SyncVersion = 0; } public void MarcarAlterado(string alteradoPor) { AlteradoEm = DateTime.UtcNow; AlteradoPor = alteradoPor; SyncVersion++; } public void Deletar(string deletadoPor) { DeletadoEm = DateTime.UtcNow; // soft delete — nunca context.Remove() AlteradoPor = deletadoPor; } public bool EstaAtivo() => DeletadoEm == null; public bool IsValid => !Notifications.Any(); }
ContextBase — QueryFilter automático por reflection
protected override void OnModelCreating(ModelBuilder modelBuilder) { var method = typeof(ContextBase) .GetMethod("AplicarFiltroTenantESoftDelete", BindingFlags.NonPublic | BindingFlags.Static); foreach (var entityType in modelBuilder.Model.GetEntityTypes()) { if (entityType.ClrType.IsAssignableTo(typeof(EntidadeSaaSBase))) { method!.MakeGenericMethod(entityType.ClrType) .Invoke(null, [modelBuilder, this]); } } } // Aplicado a TODAS as entidades automaticamente — nunca esquece // WHERE tenant_id = {TenantProvider.GetTenantId()} // AND deletado_em IS NULL
Regras SEMPRE e NUNCA

✅ SEMPRE

✓ Herdar EntidadeSaaSBase em toda entidade
✓ DateTime.UtcNow — nunca DateTime.Now
✓ Guid para IDs — nunca long sequencial
✓ Soft delete via entidade.Deletar(userId)
✓ ITenantProvider via DI — nunca estático
✓ Schema por módulo no mapping EF Core
✓ snake_case nas colunas PostgreSQL
✓ CQRS — zero lógica no Controller
✓ Outbox Pattern para todo Domain Event
✓ Precision(18,2) em todo campo decimal
✓ Índice composto (tenant_id, campo_negocio)
✓ Índice único em sync_id

❌ NUNCA

✗ context.Remove() — soft delete apenas
✗ Lógica de negócio no Controller
✗ DbContext de outro módulo injetado
✗ Variável estática de TenantId
✗ JWT ou secret no código fonte
✗ Connection string em appsettings de produção
✗ Entidade sem herdar EntidadeSaaSBase
✗ long ou int como ID de entidade
✗ DateTime.Now em qualquer lugar
✗ Domain Event publicado diretamente
✗ SQL raw sem parâmetros
✗ Cross-schema query sem documentação

Bugs críticos do Epros.ERP legado — corrigidos por design
Estes bugs existem em produção nos 20 clientes Epros.ERP. A reescrita resolve todos por arquitetura — não por correções pontuais. Não é possível "corrigir" individualmente sem refatorar a base.
Bug no legado Impacto em produção Solução Epros
TenantData.TenantIdStaticVariável estática global. Em concorrência, Thread A pode ler TenantId da Thread B — vazamento de dados entre clientesITenantProvider scoped via IHttpContextAccessor. Cada request tem seu próprio contexto de tenant.
JWT secret hardcodedSecret fixo no appsettings. Sem MFA. Sem revogação de sessão. Sem SSO. Rotação manual é inviável.Keycloak 24 com OIDC. MFA TOTP + WebAuthn. Revogação imediata de sessões. Token 15min.
SQL Server (licença)Custo de licença por cliente. Vendor lock-in da Microsoft. Sem pgvector, pgcrypto, particionamento adequado.PostgreSQL 16 open source. Zero licença. pgcrypto para PII, pgvector para IA, pg_trgm para busca.
DateTime.Now em todo códigoUsa timezone local do servidor. Bugs de horário de verão. Registros com hora errada. Inconsistências em multi-servidor.DateTime.UtcNow obrigatório. Convenção no ContextBase. Regra de PR bloqueia DateTime.Now.
IDs long sequenciaisImpossível gerar ID offline (precisa de banco). Colisão ao mesclar dados de dois ambientes. Enumerable via URL.Guid em todas as entidades. Gerado localmente no construtor. Offline-safe. Não enumerável.
PDV offline com FirebirdBanco Firebird embutido. Pesado (25MB+). Sincronização manual frágil. Licença proprietária. Sem solução de conflito.SQLite via Electron. Leve, confiável. SyncEngine com SyncVersion para detecção de conflitos. For UPDATE SKIP LOCKED.
Controllers com 40k–191k linhasCompraController: 3.294 linhas. VendaController: 2.535. VendaNfeController: 2.739. Impossível testar, manter ou evoluir.CQRS: handler por operação (~50–100 linhas cada). Testável isoladamente. Sem estado compartilhado.
QueryFilter manual por entityCada entidade precisava de WHERE manual. Fácil esquecer. Vazamento de dados entre tenants silencioso.ContextBase com reflection automático. Impossível esquecer — aplica em toda entidade que herda EntidadeSaaSBase.
TenantMiddleware comentadoO middleware de validação de tenant estava desabilitado em produção. Zero validação de tenant em cada request.InquilinoSaaSMiddleware implementado, testado e com suite de integração obrigatória (tenant leak A/B).
Blazor WASM no painel adminStack diferente do ERP. Time dividido entre Vue/Nuxt e Blazor. Build lento (5min+). DLLs .NET no browser.Nuxt 3 unificado. Um time, uma stack, um pipeline CI. Build em segundos.
