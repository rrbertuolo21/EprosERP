Serviços & Integrações

Documentação das interfaces de comunicação com parceiros externos, emissão fiscal governamental, processamento de pagamentos e federação de identidades.

Emissão de Documentos Fiscais Eletrônicos (DFe)

O módulo Fiscal conecta-se diretamente aos Web Services estaduais da SEFAZ para emissão de NF-e (modelo 55) e NFC-e (modelo 65) utilizando a biblioteca proprietária homologada `Hercules.NET.NFe.NFCe`.

1
Geração do XML: O comando `EmitirDocumentoFiscalCommand` monta o XML com o schema nacional correspondente com base nos dados de vendas/compras.
2
Assinatura Digital: O monólito recupera o Certificado Digital A1 do tenant (armazenado com criptografia AES-256 em tabelas protegidas) e assina o XML.
3
Transmissão síncrona/assíncrona: O arquivo assinado é enviado via protocolo SOAP seguro para a respectiva SEFAZ autorizadora.
4
Persistência de Retorno: O protocolo de autorização retornado é gravado no banco de dados e o XML assinado é gravado no storage persistente MinIO S3.
Resiliência Operacional & Contingência NFC-e Offline
REGRA CRÍTICA: As operações de frente de caixa (PDV) não podem parar em caso de indisponibilidade de internet ou instabilidade da SEFAZ. O Epros.Mobile possui um fluxo nativo de contingência offline.
  • 1
    Detecção de Instabilidade: O aplicativo local monitora a latência das requisições e a saúde da SEFAZ. Se a comunicação cair ou demorar mais de 10 segundos, o PDV entra automaticamente em modo Contingência Offline (Offline Contingency).
  • 2
    Emissão Local: O XML da NFC-e é gerado localmente com a tag de tipo de emissão correspondente a contingência (`tpEmis = 9`), assinado localmente com par de chaves móveis e impresso imediatamente para o cliente.
  • 3
    Sincronização Tardia: Quando o sistema detecta que a conexão de rede foi reestabelecida, um Worker em background no SQLite local transmite todos os XMLs de contingência acumulados em segundo plano para o monólito em até 24 horas (prazo regulatório brasileiro).
Processamento e Cobrança Automática via Mercado Pago

O faturamento de assinaturas SaaS da plataforma e as vendas nos PDVs dos inquilinos são integrados nativamente com o gateway do Mercado Pago, fornecendo liquidação instantânea e baixo custo transacional.

Fluxo de Cobrança Pix

1. A API cria uma ordem de pagamento (Preference ou Payment) enviando o payload para a URL do Mercado Pago.

2. O MP retorna a chave Pix (copia e cola) e a string Base64 do QR Code, renderizados imediatamente na UI.

3. Um token de idempotência associado à Fatura do inquilino impede duplicações em nível de banco de dados.

Tratamento de Webhooks & MediatR

1. Ao receber a confirmação, o Mercado Pago dispara um webhook `POST /api/v1/financeiro/webhooks/mercadopago`.

2. O webhook consome o endpoint de forma anônima e valida a assinatura digital do payload para garantir autenticidade.

3. O endpoint dispara `BaixarFaturaCommand` via MediatR, alterando o status da cobrança para `Paga` e ativando reativamente os limites comerciais do tenant.

Exemplo de Payload de Webhook Válido
{ "id": "1234567890", "action": "payment.created", "api_version": "v1", "data": { "id": "9876543210" }, "date_created": "2026-06-08T15:00:00Z", "type": "payment", "user_id": "epros_saas_mp_id" }
Autenticação Unificada OIDC & Federação AD/LDAP via Keycloak

O Keycloak gerencia toda a camada de Identity Providers (IDP), tokens JWT baseados em OIDC e federação de usuários corporativos com Active Directory ou LDAP.

Fluxo / Recurso Descrição Técnica Benefício Corporativo
Direct Access Grants (ROPC) Utilizado pelo frontend desktop `Epros.App` (Electron + Nuxt 3) para realizar login diretamente na UI nativa com fluxo seguro de credenciais, sem necessitar de popups do navegador. UX integrada em aplicativos desktop locais.
JWT Claim TenantId O payload do token gerado pelo Keycloak contém a claim customizada `"tenantId"`, mapeada dinamicamente com base no grupo ou organização ao qual o usuário pertence. Garantia de segurança no isolamento lógico de RLS no PostgreSQL.
User Federation (LDAP/AD) Inquilinos de nível Enterprise (Tier 3) podem configurar o Keycloak para federar credenciais diretamente no seu Active Directory interno, sincronizando senhas e grupos corporativos. Elimina a necessidade de cadastros duplicados e atende políticas corporativas de segurança.
Estrutura Interna da Claim JWT

Quando o monólito recebe o bearer token no header, a claim customizada é lida pelo middleware de autenticação e injetada no escopo do `ITenantProvider`:

{ "sub": "38db98bc-a82f-488b-a7a7-19cb5710aa7d", "email": "gestor@cliente.com", "name": "Gestor Epros", "roles": [ "admin", "estoque.produtos.write" ], "tenantId": "tenant-exemplo-abc-123" }
Rede de Marketplaces & Logística

O módulo de Vendas e Estoque integra-se a hubs externos para consolidar estoque físico e precificação e calcular taxas de frete de transportadoras.

Cálculo de Frete (Melhor Envio / Correios)

O cálculo de taxas e prazos de entrega consome a API do Melhor Envio de forma transparente durante a simulação de vendas ou checkout.

A API calcula o frete com base nas dimensões do produto (comprimento, largura, altura e peso) cadastradas na entidade `Produto` do Estoque.

Sincronização de Estoque com Marketplaces

Integração via webhook de atualização de estoque com Hubs parceiros (como Anymarket ou Tray) para manter o inventário em paridade com canais de vendas.

A cada movimentação de estoque física gerada no monólito (`MovimentoEstoque`), uma mensagem de outbox correspondente é publicada para notificar os canais digitais externos.

Decisões de Comunicação Externa (ADR API)
Circuit Breaker Integrado (Polly)
Se a API da SEFAZ ou do Melhor Envio apresentar timeouts repetidos, o circuito abre por 60 segundos, retornando automaticamente um fallback local (contingência offline para SEFAZ e preço de frete em cache estático para Melhor Envio) para proteger o thread pool da API.
Rate Limiting por Tenant
As requisições externas recebidas nos webhooks são limitadas a **60 chamadas por minuto** por tenant ativo para mitigar ataques de negação de serviço e abuso de consumo de infraestrutura.
